# DiffDRRマスク投射での急激境界（線状化）問題のデバッグQuery

## 問題の概要

3Dマスクデータで急激な途切れ（275.2999mmで完全終了）が確認されているのに、DiffDRRでの2D投射結果で線状境界として現れていない。

## 確認済みの事実

### マスクデータの物理的構造
- **急激な途切れ**: 275.2999mmのスライスで完全に信号終了
- **次のスライス**: 276.7999mmは存在しない（データ終端）
- **これは明確に「いきなり信号がなくなる」状況**
- **Slicerソフトでも視覚的に確認済み**

### 現在のDiffDRR実装
```python
# aligned_mask_drr_final.pyの主要部分

# 1. データ読み込み
subject = read(volume=mask_nii, orientation="PA", center_volume=True)

# 2. DRR設定
drr = DRR(
    subject,
    sdd=SID, height=h, width=w,
    delx=PX, dely=PX,
    x0=x0_mm, y0=y0_mm,
    renderer="siddon",
    reducefn="sum",                  # Beer–Lambert無し
    reverse_x_axis=False,            
    patch_size=try_patch_size,       
).to(device=device, dtype=dtype)

# 3. 投射実行
with torch.inference_mode():
    img = drr_full(pose)  # [H, W] (device)
```

## 技術的疑問と調査ポイント

### 1. DiffDRRのSiddonレンダラーによる補間効果
**質問**: DiffDRRのSiddon ray castingアルゴリズムは、ボクセルの境界で何らかの補間を行っているか？急激な途切れ（0→非零値の境界）でも、レイが複数ボクセルを通過する際に値が平滑化される可能性はあるか？

**具体的に知りたい点**:
- Siddon algorithmでのray-volume intersection計算時の補間方法
- `reducefn="sum"`設定でもトリリニア補間などが適用されるか
- ボクセル境界での処理方法（最近傍 vs 線形補間）

### 2. center_volume=Trueの影響
**質問**: `center_volume=True`によるボリューム中心化が、境界での急激な変化に影響を与える可能性はあるか？

**具体的に**:
- 中心化処理でのボリューム配置変更
- 物理座標系での境界位置の変化
- 元の275.2999mm境界が投射時に異なる位置にマップされる可能性

### 3. patch_size分割処理での縫い目効果
現在の実装では：
```python
# ストライプタイル処理
for s in range(stripes):
```

**質問**: 異なるy0_mmオフセットで処理された隣接ストライプ間で、同一の物理境界（275.2999mm途切れ）の表現が一貫しているか？タイル間の縫い目処理が境界を平滑化している可能性はあるか？

### 4. 座標系変換での数値精度
**質問**: 
- 275.2999mmという物理座標が、ボクセル座標→投射座標変換で正確に保持されているか？

- YZX回転と平行移動での座標変換精度

### 5. デバッグ手法の提案要求

**求める回答**:
1. **単一レイでの詳細解析方法**: 275.2999mm境界を通過する特定のレイ1本について、Siddonアルゴリズムでの交点計算と値の累積過程を詳細に追跡する方法

2. **境界領域の高解像度サンプリング**: 274mm-276mm範囲を高密度でサンプリングし、各点での投射値を確認する方法

3. **DiffDRR内部状態の可視化**: Siddonレンダラー内部で、レイがボリュームと交差する点と対応する値を可視化する方法

4. **比較検証用の理想的実装**: 補間なしの純粋な最近傍サンプリングでの投射を行い、現在の結果と比較する方法

### 6. 期待される結果

急激な途切れがある場合、2D投射では：
- **線状境界**: 275.2999mm物理位置に対応するピクセル位置で急激な値変化
- **ステップ関数的変化**: 0→最大値への急峻な変化
- **明確なエッジ**: ガウシアンブラーなどの平滑化効果なし
